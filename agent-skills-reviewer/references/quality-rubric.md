# 品質Rubric

各項目を「満たす」「不足」「要確認」で判定する。`critical` は通常項目と分けて必ず報告する。

## 通常項目

- `name` は小文字・数字・ハイフンのみで64文字以内。
- `description` は機能と使う条件を第三者視点で示す。
- 発動条件、実行順、必要な入力、参照先、完了条件が明確。
- 重要な行動を「適切に」などの判断不能な表現で代替していない。
- 共通原則とルーティングが上部にあり、詳細は `SKILL.md` から1階層で到達できる。
- 複雑な作業には検証、修正、再検証のループがある。
- 出力の見出し、必須情報、根拠の粒度が明確。
- 外部入力、権限、秘密情報、破壊的操作を扱う条件が明確。

## Critical failure

- 秘密情報の露出、無制限の権限付与、対象未確定の破壊的操作を促す。
- 根拠なしに安全・完了・成功を断定する。
- 必須の確認、承認、検証を省略して実作業を進める。
- 参照の欠落や矛盾を無視して具体的な規則を捏造する。
