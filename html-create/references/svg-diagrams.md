# SVG 作図ガイド

## 読む順序

1. 文章・表より図のほうが関係を理解しやすいか判断する。単純な直列手順は番号付き説明にする。
2. 文脈と伝えたい関係から図の構成を決める。下の39種類は参考パターンであり、必ずどれかに分類する必要はない。参考になる資料だけを読み、必要なら独自の図や既存パターンの応用・組み合わせを設計する。関連する派生型は同じ資料内にある。
3. 入力の事実と図で伝える結論を整理し、描画・表示確認を行う。種類や見た目だけのために確認待ちを挟まない。

## 設計と描画

- 独自の図にも、共通の見た目・読み上げ・数量の正確性・表示確認を適用する。独自の記号や配置の意味は本文や凡例で説明し、既存図法の記号を別の意味へ流用しない。組み合わせる場合は、各部分の関係や軸の意味が混同されないようにする。

- 図の主張、要素、関係、数量、出所を先に確定する。サンプルの架空データを実データとして使わない。原典の重要な図は既存方針に従い出所を明記して引用する。
- 表示幅から文字とノードの寸法を決める。日本語は文字数だけで幅を決めず、ブラウザの実表示で確認し、`text` と `tspan` で意味の切れ目を改行する。
- ノードが9個を超える場合は概要と詳細への分割を検討する。これは削除の許可や一律上限ではない。省略・集約した情報は説明する。
- 目安として内側余白12〜16、ノード間24〜40、ラベルと線6〜10の間隔から始める。いずれもSVG座標単位であり、縮小後の画面上の余白を保証しない。
- 描画順は背景・領域・接続線・ノード・ラベルを基本とする。線は別のノードの下を通さず、ラベルもノードに重ねない。ラベルの背景が必要なら置かれる面と同色にする。
- 構成図などの接続線は水平・垂直と角丸の折れ曲がりを使う。別の接続線とは12程度離し、同じ辺への接続位置を分ける。交差を避けられない場合は小さな橋形の弧で非接続を表す。
- 階層図の共有幹線、生存線を横切るメッセージ、循環や状態遷移の曲線、特性要因図・ウォードリーマップの斜線、数量を表す線や帯には各図の規則を使う。データを直角配線やグリッドに合わせて動かさない。
- 矢印は方向が意味を持つ場合だけ付け、実際に使うマーカーだけ定義する。関係を示す白三角・菱形などは通常の矢印と区別する。

## 見た目と数量

- 白い表示面 `--mb-surface`、黒線・文字 `--mb-ink`、補助文字 `--mb-muted` を使う。自然言語は `--mb-font-sans`、コード・URL・日付などは `--mb-font-mono` を使う。
- 系列は線種・形・直接ラベルで区別する。淡い塗りだけを意味の手掛かりにせず、意味のある輪郭には黒を使う。赤は既存の文書全体の強調規則に従い、図ごとの追加枠を設けない。
- 軸・単位・範囲・出所を示す。尺度を共有すべき箇所は同じ変換式を使い、データ座標を装飾用グリッドへ丸めない。
- 欠損と0を区別する。量が全ゼロのときは有限の軸範囲や「合計0」の表示へ切り替え、ゼロ除算を避ける。比率・面積・帯幅を読みやすさのために改変しない。
- 概念的な面積・位置と、測定値に比例する面積・位置を明示的に区別する。必要なら本文で実値を併記する。

## HTML への埋め込み

```html
<figure class="mb-figure">
  <div class="mb-figure-frame">
    <svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 320 160"
         width="320" role="img" aria-labelledby="topic-1-title topic-1-desc">
      <title id="topic-1-title">図の主題</title>
      <desc id="topic-1-desc">関係や数量を、図なしでも理解できる一文で説明する。</desc>
      <!-- 選んだ図の要素を配置する -->
    </svg>
  </div>
  <figcaption>図1：図の要点。出所または自作であること。</figcaption>
</figure>
```

- `title` はSVGの最初の子に置く。`aria-labelledby` に `title` と `desc` のIDを列挙する。
- 同一文書中のすべてのIDを一意にする。タイトルだけでなく、マーカー・クリップ・パターンと `url(#...)` の参照も図ごとの接頭辞に揃える。
- 装飾だけのSVGは `aria-hidden="true"` とし、図としての読み上げ名を付けない。
- 成果物は既存どおり単一HTMLとし、共通CSSをそのまま埋め込む。図のための外部スクリプト・アイコン集・描画ライブラリは不要。
- 最小作例は320座標単位の幅で配置されている。実際の内容を入れるときは寸法を再計算する。モバイルで潰れる横長図は、関係を維持した縦配置や概要と詳細への分割を優先する。

## 完了前の確認

- 参照した図の検証項目を使い、独自の図では意図した記号・配置の意味も確認する。いずれも要素・関係・実値が入力と一致するか確認する。
- 通常幅・狭い画面・印刷表示で文字の欠け、ノードとラベルの干渉、矢印先端、SVG領域外へのはみ出しを確認する。重要なラベルは実表示で14px程度以上を目安にする。
- 複数図のID衝突、参照切れ、読み上げ名、色なしでの意味の識別を確認する。
- ブラウザで確認できなかった場合は静的検査と区別して報告する。PDF生成は明示的な依頼がある場合だけ実施する。

## 対象外と出典

- この統合は静的なインラインSVGの作成手順を提供する。元プラグインのブランド登録、暗色テーマ、アニメーション、外部形式の取り込み、PNG・SVG書き出しコマンドは含まない。
- [転用元とライセンス](diagram-attribution.md)。別途 `diagram-design` をインストールする必要はない。
