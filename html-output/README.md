# html-output

会話内容を見やすい単一HTMLに変換し、ローカルPC内へ保存して、そのファイルパスを返すAgent Skillsです。

Thariq（`@trq212`、Claude Code / Anthropic、prev YC W20, `@southpkcommons`, `@medialab`）は、エージェントの出力が長く複雑になるほど Markdown は読みにくく、表現力も足りなくなると主張しています。
そのうえで、HTML なら表、配色、図、コード、レイアウト、簡単なインタラクションまで 1 ファイルで表現しやすいと述べています。
特に、仕様書、調査レポート、コードレビュー、設計比較のような「一度で理解したい文書」は HTML の方が読みやすい、という立場です。
Claude Code はコードベース、Git 履歴、各種コンテキストを読んだうえで HTML を組み立てられるので、単なる装飾ではなく理解補助になる、というのが中核の主張です。
このスキルは、その考え方をローカル保存向けに扱いやすくしたものです。

> Markdown の長文をそのまま読ませるのではなく、重要な数値、比較、図、結論を 5 秒で把握できる HTML に変換し、あとからローカルで開き直せる形にします。

## 概要

このスキルは、Markdownを 1 枚の自己完結型 HTML に変換して、ローカルディレクトリへ保存します。

生成される HTML は次の方針で作られます。

- CSS はインライン
- SVG はインライン
- CDN は使わない
- 1 ファイルで完結する
- ブラウザでそのまま開ける

保存後は共有URLではなく、ローカル上の絶対パスを返します。

```text
/Users/you/html-output/setup-guide-4f0e78eb.html
```

## ローカル保存にする理由

ローカル保存前提にすると、セットアップと運用がかなり単純になります。

- 外部クラウドのアカウントが不要
- 認証情報の管理が不要
- 誤って外部公開する事故を避けやすい
- オフライン寄りの運用がしやすい
- 保存先の実体が分かりやすい

一方で、返されるのはローカルパスなので、そのまま他人に送っても相手の環境では開けません。
共有したい場合は、別の配布方法をユーザー側で選ぶ前提です。

## 向いている用途

- 長い調査メモを 1 枚の HTML にまとめたい
- 比較表、コード、図、結論をひと目で読める形にしたい
- 会話の内容をあとでローカルで見返したい
- Markdown のままでは読みにくい出力をブラウザ向けに整えたい

## ファイル名ルール

保存名は 3 パターンあります。

- 引数なし
  - `<YYYY-MM-DDTHHMM>-<8hex>.html`
  - 一時的な出力向け
- 名前を渡す
  - `<slug>-<8hex>.html`
  - 後で探し直したい文書向け
- `.html` で終わる完全な名前を渡す
  - その名前で保存
  - 同じパスを維持したまま更新したい場合向け

名前を渡した場合は、自動でスラッグ化されます。
たとえば `"Setup Guide"` を渡すと `setup-guide-<8hex>.html` になります。

`8hex` は 32-bit 相当のランダム値で、意図しないファイル名衝突を避けるために使います。
より衝突確率を下げたい場合は、[scripts/publish.sh](/home/masato/Workspace/html-output/scripts/publish.sh) の `secrets.token_hex(4)` を `secrets.token_hex(8)` に変更してください。


## 初回セットアップ

### 1. 設定ファイルを作る

```bash
cp ~/.claude/skills/html-output/config.example.json ~/.claude/skills/html-output/config.json
$EDITOR ~/.claude/skills/html-output/config.json
```

設定例:

```json
{
  "output_dir": "~/html-output",
  "footer_text": "Generated by Claude Code"
}
```

### 2. 保存先ディレクトリを作る

```bash
mkdir -p ~/html-output
```

## Coding Agentからの使い方

直接 `/html-output` を呼んでもよいですし、自然文で次のように頼んでも使える想定です。

- `HTML化して`
- `ブラウザで見やすい形にして`
- `あとで見返せるHTMLにして`
- `ローカルに保存する形でまとめて`

## 実際に何をするか

1. Coding Agent が 1 ファイル完結の HTML を生成します。
2. その HTML を標準入力で `scripts/publish.sh` に渡します。
3. `publish.sh` が `config.json` を読み、保存先とファイル名を決めます。
4. HTML を `output_dir` 配下へ保存します。
5. 保存した HTML の絶対パスを返します。

## スクリプトを直接使う例

### 標準入力から保存する

```bash
cat report.html | bash scripts/publish.sh
```

### 名前付きで保存する

```bash
cat report.html | bash scripts/publish.sh setup-guide
```

### 既存ファイルを入力にする

```bash
bash scripts/publish.sh path/to/file.html
```

### 保存済みHTMLを探す

```bash
bash scripts/list.sh
bash scripts/list.sh setup-guide
bash scripts/list.sh setup-guide --keys-only
```

## ローカルアーカイブとしての使い方

`scripts/list.sh` を使うと、保存済みの HTML を接頭辞で探せます。
そのため、このスキルは単発の出力だけでなく、「あとで探せるローカル文書置き場」としても使えます。

ただし、返される絶対パスはマシン依存です。
HTML 内に `file://` リンクや絶対パスを埋め込むのは、同じPC内でだけ使う前提のときに限るのが安全です。

## 注意点

- HTML は自動削除されません
- 一時出力を多用すると `output_dir` にファイルが蓄積します
- 他人に渡すには別の共有手段が必要です
- ローカル保存なので、別PCでは同じパスをそのまま再利用できません

## ディレクトリ構成

```text
html-output/
├── SKILL.md
├── config.json
├── config.example.json
├── scripts/
│   ├── publish.sh
│   └── list.sh
└── references/
    └── setup.md
```

各ファイルの役割:

- `SKILL.md`
  - Coding Agent が参照するスキル定義
- `config.json`
  - ローカル環境ごとの個別設定
- `config.example.json`
  - 設定テンプレート
- `scripts/publish.sh`
  - HTML を保存して絶対パスを返す
- `scripts/list.sh`
  - 保存済みHTMLを列挙する
- `references/setup.md`
  - 初回セットアップ手順
