# コード規模の集計

指定フォルダを走査し、言語別・ファイル別の行数(総行数 / コード行 / コメント行 / 空行)を集計して、HTML レポートとチャット内の表で整理する。計測は必ず同梱スクリプトで行い、モデルがファイルを読んで概算しない。あて推量で行数を答えない。

## 手順

1. 集計対象フォルダを確定する。ユーザーの指定がなければ現在の作業ディレクトリを対象にし、その旨を伝える。
2. 計測スクリプトを実行する(HTML レポートが同時に生成される):

   ```bash
   python3 "<このスキルのディレクトリ>/scripts/count_code.py" <対象フォルダ> --format html
   ```

   - レポートはカレントディレクトリに `{yyyymmdd}-code-scale-report.html` として保存される。デザインシステムの CSS は HTML 内に埋め込まれているため、この 1 ファイル単独で移動・共有できる(html-create のデザインシステムに従う)。ブラウザで開くようユーザーに案内する。
   - 出力先を変えるなら `--output <パス>`、CSV は `--format csv`、JSON は `--format json`、コンソール表示だけなら `--format text --top 20` を使う。
   - `.git`、`node_modules`、`venv`、`dist`、`build` などの除外ディレクトリの一覧と、各オプションの詳細はスクリプトの `--help` を参照する。
3. 集計結果をチャット内に Markdown 表で整理する(HTML はチャットでレンダリングされないため):
   - 冒頭に一言で全体規模を要約する(例:「全体で 42 ファイル・8,200 行、コード行は 6,100 行でコメント率 12.3%」)
   - 言語別サマリー表(言語 / ファイル数 / コード行 / コメント行 / 空行 / 総行数)は必ず全言語出す
   - ファイル別の表は各言語コード行降順で、全体が小さい(30 ファイル程度まで)なら全件、大きいなら上位 10 件に留め、残りはレポートを参照させる
   - 表は日本語ヘッダーで、数値は 3 桁区切りにする
4. スクリプトの標準出力に「レポート: <パス>」が出るので、その絶対パスを結果の末尾にリンクとして示す。

## 集計ルール

- **コメント行** = 行頭(空白を除く)がコメント記号で始まる行。ブロックコメント内の行を含む。行末にコメントが付く行はコード行
- **空行** = 空白のみの行
- **コード行** = 総行数 − コメント行 − 空行。Python の docstring(トリプルクォート)は文字列リテラルとしてコード行に数える
- 文字列リテラル内の `//` や `#`(URL など)はコメントと誤判定しない設計になっている
- 対応言語は Python / JavaScript / TypeScript / Java / C 系 / Go / Rust / Ruby / PHP / Shell / SQL / HTML / CSS / YAML / JSON / Markdown など約 40 種。拡張子が未知のテキストは「その他」として総行数・空行のみ数える
- コメント率の定義は コメント行 ÷ 総行数。ユーザーが「コメント抜きの規模」を聞いたらコード行を答える

## 注意

- 集計結果の数値はスクリプトの出力をそのまま使う。自分で数え直したり端数を丸めたりしない
- 対象が巨大な場合もスクリプトは数秒で終わる。ファイル一覧を自分で列挙しない
- ユーザーから「Markdown で出して」など形式指定があれば `--format` を切り替えて対応する
- HTML レポートの見た目を変える場合は、html-create スキルのデザイン規約(背景 `#FAF9F6`、白地 + 黒罫線 + 角丸、字体 2 系統、有彩色はリンク青とアクセント赤のみ)に従う
